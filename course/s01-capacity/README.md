## 这一课的整体知识（人话版）

> 这一节是 D2 的知识底座：下面记录“做了什么、看到了什么”，这里回答“这课到底在讲什么”。复习时先读这一节，再回看案例。

**一句话**：训练任务能不能跑，看每张卡装不装得下模型状态和激活；跑得快不快，看扣掉流水线气泡后的有效时长。平台把这三本账算清楚，Infra 据此决定 TP/PP/DP/ZeRO。

### 1. 三本账

- **模型状态**：每个参数固定 16 字节，按 TP×PP 切，ZeRO 再按 dp 切其中一部分。
- **激活**：随序列长度、层数、micro-batch 变化，按 PP 分层、按 TP 切宽度，不按 dp 切。
- **算力**：训练总量约 6ND，full recompute 是 8ND；除以卡数、峰值和 MFU 得到时长。

三本账对应三个问题：每卡装多少、总共算多少、并行浪费多少。前两本决定 OOM，第三本和气泡一起决定快慢。

### 2. 模型状态：16 字节与 ZeRO

**16 字节 = BF16 权重 2 + BF16 梯度 2 + FP32 主权重 4 + Adam 动量 m 4 + Adam 方差 v 4。**

为什么要留 FP32 主权重：BF16 尾数只有 7 位，参数更新量很小时会被舍入掉；保留一份 FP32，更新时用它，更新完再转回 BF16 给前向。

ZeRO 的切法是：

```
ZeRO-0：16Ψ / (tp·pp)
ZeRO-1：(4Ψ + 12Ψ/dp) / (tp·pp)
ZeRO-2：(2Ψ + 14Ψ/dp) / (tp·pp)
ZeRO-3：16Ψ / (tp·pp·dp)
```

关键不是背公式，而是知道什么能切：**4Ψ（权重+梯度）前向反向每卡都要用完整一份，不能切；12Ψ（主权重+m+v）只在更新时用、每个参数独立，才能按 dp 切。** 一句话：前向反向要用的不切，只在更新时用的才切。

7B、tp=pp=1、dp=8 的例子：ZeRO-0 是 112 GB，ZeRO-1 是 38.5 GB，ZeRO-2 是 26.25 GB，ZeRO-3 是 14 GB。换资源的两句话：**ZeRO 用通信换显存，recompute 用算力换显存。**

### 3. 激活：为什么 attention 那么贵

单层激活的三种口径：

```
none：      s·b·h·(34 + 5as/h)
selective： 34·s·b·h
full：      2·s·b·h
```

- **34 是线性项**：随 `s·b·h` 线性增长的激活。按 Megatron 论文口径可粗拆成 attention 线性部分 10 + MLP 线性部分 24。它不是物理常数，会随实现、融合算子、mask 保留策略变化。
- **5as/h 是 attention 平方项**：每个 head 的分数矩阵是 `s×s`，每个分数存 5 字节（分数 2 + softmax 输出 2 + dropout mask 1），总计 `5·a·s²·b` 字节；除以 `s·b·h` 后写成 `5as/h`。
- **s² 从 QK^T 来**：每个 query token 都要和每个 key token 算相似度，所以是 `s×s`；序列翻倍，这一项变 4 倍。

每卡激活 = 单层激活 × layers / pp / tp。**PP 决定这张卡参与几层，TP 决定每层被拆几份，dp 不切激活**——每张卡跑不同的 micro-batch，激活天然不同，没有重复可省。

selective 的取舍：attention 的 s² 项占显存多、重算便宜，砍掉；线性项占得少、重算贵，保留。所以 selective 砍掉“占得多但重算便宜”的 attention，保留“占得少但重算昂贵”的线性层。

### 4. 算力：6ND 与 8ND

```
C = 6·N·D FLOPs          # 前向 2ND + 反向 4ND
C = 8·N·D FLOPs          # full recompute 多算一遍前向
hours = C / (gpus × peak_tflops × 1e12 × mfu) / 3600
```

单位陷阱：`N = params_b × 1e9`，`D = tokens_t × 1e12`。B 和 T 之间差 `1e18`，先展开成“个”再相乘。7B × 1T = 7e21，不是 7。

1000×H100、7B、1T、MFU 0.4：`C = 4.2e22` FLOPs，有效算力 `3.956e17` FLOP/s，约 29.5 小时。这是纯算力下界，没计气泡、通信、数据加载和故障重启。

### 5. 气泡与有效时长

流水线有 pp 个 stage、m 个 micro-batch。前 pp-1 步是填充，后 pp-1 步是排空，总步数 m+pp-1，每个 stage 空闲 pp-1 步：

```
bubble = (pp - 1) / (m + pp - 1)
effective_hours = hours / (1 - bubble)
```

m 越大，气泡越小；pp 越大，气泡越大。工程上常要求 `m >= 2pp`。**OOM 只是门槛，吞吐才是分数**：能进候选的都不 OOM，再按有效时长排序，而不是按“谁最省显存”。

### 6. 平台与 Infra 的边界

**平台不替 Infra 决定 TP/PP/DP/ZeRO。** 平台提供资源画像（单机卡数、HBM、NVLink 域、配额、拓扑），提供容量计算器和准入校验，保存配置与 rank 证据；切法由 Infra 根据模型结构、框架和通信拓扑决定，并显式写进启动脚本。平台不偷偷改写脚本。

一句话：**平台把资源和后果算清楚，切法由 Infra 写。**

### 7. toy 和真实的距离

这套模型没计通信缓冲区（记 0）、把 selective 近似成 6ND、只按 1 个 micro-batch 估激活、TP/ZeRO 通信未定价、scan 默认只枚举 ZeRO-0/1，也没建模显存碎片、拓扑和故障域。它的价值是快速判断量级和排序，不是替代真实 profiler。面试时主动说边界，比假装精确更加分。

### 五句话带走

1. 16 字节 = 2 + 2 + 4 + 4 + 4；前向反向要用的不切，只在更新时用的才切。
2. 激活按 PP 和 TP 切，不按 dp 切；attention 的 s² 来自 QK^T。
3. 6ND 是底账，full recompute 是 8ND；B 和 T 先展开成“个”再相乘。
4. 气泡 = (pp-1)/(m+pp-1)；排序看 `hours/(1-bubble)`，不是看谁最省显存。
5. 平台提供信息和后果，切法由 Infra 写；平台拦坏配置、解释慢、留证据。

## 为什么（Q1–Q7 要点卡，长版见 answer.md）

**Q1 16 字节与 FP16/BF16**

- 16 = BF16 权重 2 + BF16 梯度 2 + FP32 主权重 4 + Adam m 4 + Adam v 4。
- FP32 主权重负责接住小幅更新，避免 BF16 尾数把更新舍入掉。
- FP16 输在指数范围（5 位，最大 65504），大梯度/大激活容易溢出；BF16 有 8 位指数，范围与 FP32 同级。
- 核句：16 字节买的是稳定训练；FP16 输在指数范围，不是精度。

**Q2 34 与 5as/h**

- 34 是线性项，按论文口径可粗拆成 attention 线性 10 + MLP 线性 24，不是物理常数。
- 5as/h 是 attention 平方项；每个分数存 5 字节（分数 2 + softmax 输出 2 + mask 1）。
- s² 来自 QK^T：每个 query 都要和每个 key 算相似度，序列翻倍这项变 4 倍。
- 核句：selective 砍“占得多、重算便宜”的 attention，保“占得少、重算贵”的线性层。

**Q3 ZeRO-3 相比 ZeRO-1**

- 显存：ZeRO-1 是 `(4Ψ+12Ψ/dp)/(tp·pp)`，ZeRO-3 是 `16Ψ/(tp·pp·dp)`，省 `4Ψ(1-1/dp)/(tp·pp)`。
- 7B、tp=pp=1、dp=8：38.5 GB → 14 GB，省 24.5 GB。
- 通信：约 2Ψ → 3Ψ（前向 all-gather、反向再 all-gather、梯度 reduce-scatter），1.5×。
- 核句：ZeRO-3 用 1.5× 通信换掉最后一份 4Ψ 复制；省的是模型状态，不是激活。

**Q4 TP 为什么一般不超过 8**

- TP 每层都要 All-Reduce/All-Gather，通信频率比 DP 高一个量级。
- 一台 8 卡机器通常就是一个 NVLink 域；跨机 TP 要走 IB，带宽降、延迟升、MFU 掉。
- 跨机 TP 不是绝不能跑，而是通常不划算；`tp <= 单机卡数` 是工程约束。
- 核句：TP 的通信在每一层，必须待在 NVLink 域；8 卡一台是物理边界。

**Q5 1000×H100 训练 7B/1T**

- `C = 6ND`；N=7e9，D=1e12，N×D=7e21，先把 B 和 T 展开成“个”。
- C=4.2e22 FLOPs；有效算力 1000×989e12×0.4=3.956e17 FLOP/s。
- 时间约 1.062e5 秒 = 29.5 小时，是纯算力下界。
- 核句：6ND 除以卡数×峰值×MFU；29.5 小时不代表端到端。

**Q6 平台与 Infra 的边界**

- 平台提供资源画像：单机卡数、HBM、NVLink 域、配额、拓扑。
- 平台提供容量计算与准入校验：tp·pp·dp=总卡数、tp≤单机卡数、tp|heads、pp≤layers、m≥2pp、不 OOM。
- 切法归 Infra：模型结构、框架、通信拓扑、recompute 策略由 Infra 决定，显式写进脚本，平台不偷偷改写。
- 核句：切法由 Infra 写，平台把资源和后果算清楚；拦坏配置、解释慢、留证据。

**Q7 scan 为什么不能按 OOM 排序**

- OOM 是二元门槛，只能回答“能不能跑”，进候选的都不 OOM。
- 可行集合里要比吞吐：70B 的 TP8+selective 是 2304 h，TP4+full 是 3072 h，差 33%。
- 排序键是 `hours/(1-bubble)`，越小越快；同分再按小 TP、小 PP、省显存 tie-break。
- 核句：OOM 是及格线，吞吐才是分数。

## 结论

1. 显存按“模型状态 + 激活”两本账算；模型状态 16 字节/参数，激活按 PP/TP 切、不按 dp 切。
2. 能不能跑看 OOM，跑得快不快看 `hours/(1-bubble)`；显存最省不等于最快。
3. 并行策略的物理边界是 NVLink 域：TP 不出单机，PP/DP 可以跨机。
4. 平台不替 Infra 决定切法：平台提供资源、算清后果、校验坏配置、留下证据；切法由 Infra 写进脚本。

## 业务映射（PorryLLMOps平台）

- 表单（机器数 × 单机卡数、GPU 型号、框架）= 资源边界；平台提供的单机卡数、HBM、NVLink 域、配额和拓扑 = 资源画像。两者共同构成 Infra 做并行决策的输入。
- Infra 在启动脚本/配置里显式写 TP/PP/DP/ZeRO 和 recompute 策略；平台不替用户做这个决定，也不偷偷改写脚本。切法必须可复现、责任清晰。
- 平台的三件事（本课给出的设计口径）：**提交前**用同一套三本账枚举可行边界，并对 Infra 写下的切法做自洽、整除、TP 不超单机和 OOM 校验——当前代码已实现枚举，独立的 `validate_placement()` 留给 S7；**运行时**把实际 rank/拓扑/指标对回放置方案，解释慢在气泡还是通信；**事后**保存配置版本、rank 映射和事件时间线，失败时能回答“当时为什么这么切、哪本账超了”。
- 三种抽错的坏法：平台替 Infra 决定切法 → 不可复现、责任不清；只查 OOM → 慢 33% 的配置也算合格；不留证据 → 失败只剩一句“运行失败”。
- 价值：算法同学只需要说“我要几张卡”，Infra 拿到可行边界和每个候选的代价，平台把几千小时的资源账提前算清。

## 欠账

- 本机无 GPU，没在真实 NCCL 上跑；S2 用 4-rank gloo 做 all-reduce + checkpoint 的最小闭环，把“单机账本”推进到“分布式最小闭环”。
- 通信成本未定价：TP/ZeRO 只约束 `tp <= 单机卡数`，scan 默认只枚举 ZeRO-0/1；真实 MFU 需要实测。
- 激活按 1 个 micro-batch 估算，未建模 1F1B 在飞 `min(m, pp)` 个 micro-batch；通信缓冲区记 0；34 是论文口径。
- 未建模显存碎片、安全余量、拓扑和故障域；这些要在 S7 的放置决策里继续补。
- 当前 `capacity.py` 只有枚举函数 `feasible_placements()`：能列出可行解，但还没有独立的 `validate_placement()`、拒绝原因和运行时 rank 证据；这些是 S7/S8 的交付。
